# Criterion 1.1

Выпуск 1.1 (версия пакета 1.1.0), 14 ноября 2026: текущая версия с работающим эквайрингом, возвратом к договору после повторного входа и обработкой ошибок скачивания без ухода со страницы. Номер выпуска Criterion отличается от внутреннего номера публикации Sites. Доступ остаётся только у владельца.

Этот checkout — рабочая закрытая копия Criterion в Sites. Адрес: https://criterion-publish-diagnostic-20261113.serenewisteria2.chatgpt.site. Прежние проекты и их данные сохранены отдельно; аккаунты и договоры из них не переносились. Доступ разрешён только владельцу. По состоянию на 14 ноября 2026 (Asia/Bangkok) подключены OpenAI и рабочий терминал Т-Банка; проверены рабочая оплата, уведомления и открытие договора. Частные сведения о платежах в этот репозиторий не включены.

Рабочая реализация MVP: личный кабинет → интервью → черновик → оплата → ревью. Оплата открывает договор, Word/TXT и две ИИ-операции. Для реальных платежей проверены банковское подтверждение, доставка уведомления через VPS и открытие договора. Две ИИ-операции у оплаченных реальных заказов не расходовали. Лимит 2 → 1 → 0 и отказ третьей операции проверены ранее на DEMO и повторены изолированными тестами. См. [состояние эквайринга](docs/tbank-integration.md) и [пострелизную проверку](docs/postrelease-2026-11-14.md).

## Что реализовано

- Регистрация и вход по email и паролю; серверные сессии в D1 и изоляция документов по ID аккаунта. ChatGPT используется только для подтверждения принадлежности прежних документов при регистрации с привязкой.
- История документов в D1; восстановление сессии по URL, версии текста и возврат к предыдущей версии.
- Сбор условий через анкету или ИИ-интервью. При подключённом API оба режима составляют договор по выбранному шаблону.
- Типы: услуги, купля-продажа, аренда, подряд, NDA, другая договорённость.
- Основной авторский шаблон Criterion v.0.1: преамбула, семь разделов и реквизиты. Дополнительный образец юридических услуг выбирается в «Материалах»; персональные и паспортные данные из него удалены. Сохранены авторские условия, включая тариф и ответственность. Базовый конструктор из 12 разделов остаётся для демо и режима без API/авторского шаблона.
- API для ИИ-интервью, подготовки, проверки и пересмотра договора с валидацией ответа и неизменности структуры.
- Материалы пользователя: промпт, JSON-шаблон, правовой пакет. Копия пакета фиксируется при создании черновика.
- Ручной редактор, список замечаний, итоговая версия, настоящий OOXML `.docx`, TXT, печать/PDF через браузер.
- Оптимистическая блокировка по revision и временная серверная блокировка операции; устаревший или параллельный запрос не перетирает договор.
- При ошибке ИИ предыдущая версия не меняется; пользователь видит ошибку, а не фиктивный успех.

## Подключённые материалы и API

- `OPENAI_API_KEY` подключён серверным секретом Sites с согласия владельца. В браузер и Git ключ не передаётся.
- `OPENAI_MODEL=gpt-4.1`. Живые вызовы интервью, составления, правки и ревью проверены на вымышленных условиях в этой закрытой копии.
- Текст присланного «Промпт составления договора v.0.1.docx» сохранён без содержательных изменений в `lib/criterion/legal-defaults.ts` и применяется при составлении и ревью.
- `lib/criterion/templates.ts` содержит основной шаблон Criterion и обезличенный образец юридических услуг. По умолчанию используется Criterion; выбор образца в «Материалах» требует сохранения пакета. Стороны и их реквизиты не берутся из персональных данных автора образца.
- Формат DOCX задаётся кодом: заголовок Garamond 18, остальной текст Times New Roman 12, интервал 1.0, заданные поля, одноколонная таблица с серыми чётными строками. Наименования сторон в преамбуле и реквизитах выделяются жирным. Проверено через XML и рендер страниц.
- Правовой пакет не предоставлен. Автоматического поиска и проверки актуальности законодательства нет; это явно указано в интерфейсе.

Сайт размещён на Sites с закрытым доступом. Связь с рабочим терминалом и доставка подписанных уведомлений идут через отдельную live-службу на VPS владельца. DEMO-служба сохранена отдельно. Автоматическая проверка актуальности законодательства и юридическая сертификация не реализованы.

## Архитектура

- UI: React + Vinext, `app/workspace.tsx`, `app/globals.css`.
- Доменные модели, базовый конструктор, проверка заполненности: `lib/criterion/domain.ts`.
- LLM-адаптер: `lib/criterion/ai.ts` — отдельные операции интервью, генерации/правки и ревью. После генерации выполняется второй независимый запрос: сверка с фактами и шаблоном, исправление необоснованных дополнений. Сохраняется только прошедший обе проверки полный результат. Дополнительное ревью запускается кнопкой.
- Маршруты: `app/api/workspace`, `app/api/documents`, `app/api/documents/[id]`, `app/api/materials`.
- D1/Drizzle: `db/schema.ts`, миграции `drizzle/`.
- DOCX без стороннего сервиса: `lib/criterion/export.ts`.
- Запись данных защищена identity, ownership и проверкой Origin; входные данные валидируются Zod.

## Шаблон

Загрузите JSON-массив из 3–30 разделов с уникальными id. Для каждого нужны `id`, `title`, `content`. В `content` — согласованный образец текста или правила заполнения. ИИ обязан сохранить количество, ID, заголовки и порядок разделов. При отклонении документ не сохраняется. Отсутствующие условия обозначаются `<…>`; неизвестный выбор условия — `[вариант / вариант]`. Наличие пустого поля не мешает выгрузить черновик; итоговый статус требует явного подтверждения пользователя и не означает разрешения подписывать документ.

## Перенос

Доменная модель и ИИ-адаптер независимы от D1. Для переноса на Node/VPS замените серверную авторизацию и слой хранения, добавьте секрет окружения на сервере. Все пользовательские записи связаны с `owner`; перенос аккаунтов требует явного сопоставления идентификаторов. Worker-окружение и Sites identity не следует переносить как доверие к заголовкам из публичного интернета без проверяющего шлюза.


## Email-аккаунты и почтовые письма

`/auth` — регистрация, вход, выход, подтверждение email и восстановление доступа. Серверная почта подключается через Resend. До настройки почтовых переменных отправка отключена, интерфейс явно показывает это и сохраняет резервный способ восстановления по одноразовому коду.

Для включения нужны серверные переменные:
- `RESEND_API_KEY` — секрет с правом отправки в Resend;
- `EMAIL_FROM` — адрес отправителя на подтверждённом в Resend домене, например `Criterion <noreply@your-domain.example>`;
- `AUTH_PUBLIC_URL` — доверенный HTTPS origin приложения без пути, query и fragment. Именно он используется в письмах; входящий Host не определяет ссылку.

После сохранения переменных разверните версию и проверьте доставку на реальном почтовом ящике. SPF/DKIM и подтверждение домена выполняются в Resend/DNS. Успех API означает принятие письма провайдером, а не гарантированное попадание во входящие. Ключ, пароль и токены нельзя добавлять в репозиторий.

При регистрации настроенный сервис отправляет подтверждение, ссылка действует 24 часа. Подтверждение требует активной сессии именно соответствующего аккаунта, чтобы избежать подтверждения чужой предварительной регистрации. Для существующих пользователей в настройках доступна ссылка «Подтверждение email и восстановление доступа». Только подтверждённый email разрешает сброс пароля письмом. Резервный код остаётся доступен независимо от почты.

Ссылка сброса действует 30 минут, одноразовая; токен находится во fragment и удаляется из адресной строки после чтения. GET не расходует токен. В D1 хранятся SHA-256 токенов, их назначение, срок и привязка к версии пароля. Сброс атомарно потребляет токен, меняет пароль и код восстановления, завершает прежние сессии. Ответ на запрос сброса одинаков для отсутствующего, неподтверждённого и подтверждённого аккаунта. Отказ провайдера не возвращает ложное подтверждение доставки; он журналируется без адреса и токена. Ошибочные токены отправки удаляются.

Пароли хешируются PBKDF2-SHA256 (100 000 итераций, случайная соль; предел Web Crypto Workers). Cookie: Secure, HttpOnly, SameSite=Lax, префикс __Host-, срок 14 дней. Мутации проверяют Origin. Ограничения в D1 атомарные: для входа 10 попыток на email и 40 на IP за 15 минут; запросы писем ограничены 3 на адрес и 20 на IP в час. Регистрация отдельно ограничена лимитами входа.

Перенос прежних документов: на `/auth` открыть блок прежнего аккаунта, подтвердить вход ChatGPT, затем зарегистрироваться с отмеченной привязкой. Сохраняется прежний owner ID; документы не копируются и не удаляются. Совпадение email не объединяет аккаунты автоматически.

Миграции `0001` и `0002` добавляют аккаунты, сессии, лимиты и почтовые токены; таблицы документов не меняются. Проверки после сборки:

```sh
node tests/auth-integration.mjs
node tests/email-integration.mjs
node tests/integration.mjs
node --experimental-strip-types --test tests/mail.test.ts
```

Интеграционные тесты используют изолированную D1 и имитацию Resend. Они не отправляют реальных писем и не подтверждают фактическую доставляемость.
