# Диагностика Criterion

В «Логе приложения» Amvera найдите `database.ready`. Поле `databasePath` содержит путь, который сообщило открытое соединение SQLite. Владельца, права процесса и точку монтирования показывает `storage.snapshot` с `phase=after_open`. Проверка `services.health` опрашивает сайт и модуль ПДн. Успешный ответ означает, что компонент ответил на пробу. Состояние внешних провайдеров проверяется отдельно при выполнении операции.

## Как разобрать обращение

1. В инструментах разработчика браузера откройте «Сеть», выберите запрос к API и скопируйте `X-Request-ID` из заголовков ответа. При ошибке JSON-ответ также содержит `requestId`. Для поддержки достаточно идентификатора и времени обращения.
2. Найдите это значение в журнале сайта. `http.request_started` указывает метод и шаблон маршрута. В конце запроса ищите `http.request_completed` либо `http.request_failed`. Учитывайте статус, `durationMs` и, при ошибке, `stage`, `errorCode` и доступный `causeCode`.
3. Для оплаты найдите `payment.transport_started` и последнее событие транспорта с тем же `operationId`. Поиск этого идентификатора в журнале шлюза связывает обращение сайта с результатом обращения к банку. Старые версии шлюза и сайта продолжают обрабатывать запросы, но для сквозного поиска нужны обе обновлённые версии.
4. У события есть время UTC с суффиксом `Z`. При сравнении с панелью в московском времени прибавьте три часа. Например, `18:37:28Z` соответствует 21:37:28 МСК.

## Формат и настройки

Каждая диагностическая строка содержит `timestamp`, `level`, `event`, `service`, `release` и `instanceId`. Для интерфейсов, отображающих текст сообщения, предусмотрено поле `message` с меткой `Criterion diagnostics v2:`. Сервер создаёт собственный `r_<UUID>` на входе в API. Контекст следует за асинхронными вызовами в рамках запроса. Для операций используется `o_<UUID>`. У платежа запись заказа даёт устойчивый идентификатор при последующих обращениях. Значение `upstreamStatus` относится к удалённому сервису, `httpStatus` — к ответу самого приложения.

| Переменная | Назначение |
| --- | --- |
| `LOG_LEVEL` | Минимальный уровень. По умолчанию `info`. Доступны `debug`, `info`, `warn`, `error`. |
| `LOG_DEBUG_UNTIL` | Время окончания подробного режима в UTC, максимум через час. Требуется для уровня debug. |
| `SERVICE_NAME` | Имя компонента. Для сайта используйте `criterion`, для отдельного шлюза можно задать `tbank-gateway`. |
| `APP_RELEASE` | Версия сборки, например короткий Git SHA. По умолчанию `unknown`. |
| `INSTANCE_ID` | Техническая метка экземпляра. По умолчанию `unknown`. |

В `debug` действуют те же правила защиты данных. При добавлении события зарегистрируйте его в `lib/diagnostic-schema.mjs`, укажите валидаторы полей и добавьте проверку с вымышленными чувствительными данными. Для динамического адреса передавайте шаблон вроде `/api/documents/[id]`. Сообщения провайдеров, тела запросов, реквизиты, ключи и объекты исключений в журнал передавать нельзя.

## Исходная версия и откат P0

В GitHub-репозитории Sanders087/Criterion базовая ветка для этой доработки — `docker` на `7d80820`. При старте работы она совпадала по файлам с `amvera/master` на `4befed0`. Ветка `origin/master` в GitHub отсутствовала. Исходная сборка Next.js и проверка TypeScript прошли. На Windows прошли 84 теста, проверка групп процессов по SIGTERM выполняется на Linux. Четыре интеграционных набора исходной версии прошли 254 проверки. Полный ESLint исходной версии сообщил 8 ошибок и 16 предупреждений.

Аудит выявил вывод имени исключения в общем обработчике, возврат некоторых исходных сообщений по совпадению слов, передачу HTTP-заголовков в лог транспорта банка и потерю причин в обработчиках почты, ИИ и ПДн. Скрипты локальной отладки на синтетических примерах и журналы самого Next.js/Uvicorn имеют собственные форматы.

Для отката сайта разверните предыдущий проверенный образ, сохранив тот же том и переменные. Для отката шлюза верните предыдущий комплект программы и systemd unit вместе. P0 не добавляет SQL-миграций. Проверяйте результат на тестовых учётных данных через `/api/health` и запрос к защищённому маршруту. Все объявленные маршруты API возвращают идентификатор запроса, в том числе при HEAD, OPTIONS и 405. Для неизвестного URL или отказа внешнего прокси запрос может завершиться до входа в обработчик Criterion.

## Миграция и откат P1

Перед обновлением сохраните согласованную резервную копию SQLite через SQLite Backup API и проверьте её открытие на отдельном пути. Контейнер применяет `0004_business_operations` при старте. Миграция добавляет поля сверки и журнал почтовых операций. Существующие договоры, аккаунты и платёжные заказы сохраняются.

При откате старый образ проверяет каталог миграций и отклоняет базу с неизвестной ему миграцией. Остановите запись, сохраните копию текущего состояния, затем восстановите проверенную предрелизную копию на отдельном томе и запустите совместимый образ. Если после обновления появились платежи, аккаунты или письма, согласуйте перенос новых данных и сверку с банком до переключения трафика. Откат базы не отменяет операции провайдера.
