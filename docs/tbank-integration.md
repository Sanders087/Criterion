# Эквайринг Criterion: Т-Банк

## Текущее состояние: 14 ноября 2026, Asia/Bangkok

Рабочий терминал включён с согласия владельца. Рабочая оплата и фискальный чек проверены владельцем; идентификаторы и сведения о его платежах не публикуются. Оплаченные документы открываются, каждому доступны две ИИ-операции. Публичный доступ к сайту не включён.

Текущая схема: Sites → защищённая live-служба на VPS → Т-Банк. Уведомления банка идут на `https://srv678677.hstgr.cloud/criterion-tbank-live/notification`; служба передаёт их закрытому сайту с сервисной авторизацией. Приложение проверяет подпись банка, терминал, заказ, PaymentId и сумму. `TBANK_MODE=live`, адрес шлюза — `https://srv678677.hstgr.cloud/criterion-tbank-live/`. DEMO-служба и завершённый DEMO-заказ сохранены отдельно.

Для оплаты проверена страница банка с СБП, SberPay и картой; T-Pay включён в кабинете, но отображение кнопки на новой ссылке отдельно не подтверждалось. Реальные возвраты, отказ банка и доставку обычных писем аккаунта в этой пострелизной проверке не выполняли. Возвраты и отказы покрыты изолированными тестами. [Отчёт и подготовленные исправления](postrelease-2026-11-14.md).

Описания выключенных платежей, неподключённого рабочего терминала и отсутствия внешних уведомлений ниже относятся к истории настройки 13 ноября, до live-проверки. Не использовать их как описание текущего размещения. Значения секретов в документации отсутствуют; `.env.example` намеренно остаётся выключенным примером для нового окружения.

## Согласованный тариф

- Один новый договор: 199 ₽ (19900 копеек), разовая оплата.
- Анкета / ИИ-интервью и первоначальная генерация бесплатны.
- После генерации сервер сохраняет полный текст, но отдаёт неоплаченному клиенту только названия разделов и признак блокировки. Размытое превью состоит из декоративного текста, а не содержимого договора.
- Оплата открывает этот же договор, ручное редактирование, Word / TXT и печать / PDF.
- Включены две успешные ИИ-операции суммарно: правки и повторные проверки. Первоначальная генерация с внутренней проверкой не расходует этот лимит. Проверка заполненности без обращения к ИИ также не расходует его.
- Лимит уменьшается только вместе с успешным сохранением результата. Ошибки, конкурирующие запросы и повтор запроса со старой revision не списывают дополнительную операцию.
- Новый договор оплачивается отдельно. Рекуррентных списаний нет.
- Документы, существовавшие до миграции `0003`, сохраняют прежний доступ (`legacy`). Новые документы создаются как `unpaid`. Прежние документы не объявляются оплаченными и не получают фиктивных платежей.

## Реализация

| Адрес | Назначение |
| --- | --- |
| `POST /api/payments/checkout` | Принимает только `documentId`, проверяет владельца, создаёт заказ на серверную сумму и вызывает `Init` |
| `POST /api/payments/status` | Проверяет владельца и актуальный статус через `GetState`, восстанавливает неизвестный PaymentId через `CheckOrder` |
| `POST /api/payments/tbank/notification` | Принимает уведомления без пользовательской сессии; проверяет Token, терминал, заказ, PaymentId и сумму |

Запросы checkout/status требуют сессию и точный Origin. Уведомления банка вместо Origin и cookie проверяют криптографическую подпись. Подтверждение обрабатывается атомарно с выдачей доступа. Ответ банку — HTTP 200 с телом `OK`, только после сохранения.

`SuccessURL` сам по себе не выдаёт доступ. `AUTHORIZED` не считается оплатой; доступ выдаётся по `CONFIRMED`. Дубликаты не начисляют ИИ-операции. Запоздалое событие не понижает уже сохранённый статус. Полный возврат закрывает доступ, частичный сохраняет его. Возвраты действующих оплат проводятся оператором в кабинете банка; публичного API возвратов в приложении нет.

Одновременно возможен один активный заказ на документ. При потере ответа `Init` новый платёж вслепую не создаётся. После 30 секунд проверяется `CheckOrder` и затем `GetState`. Если платёж подтверждён, открывается договор. Если ссылка не была получена, а банк подтверждает исходный статус `NEW`, незавершённая попытка отменяется через `Cancel`. Повторная оплата возможна лишь после проверки закрытия предыдущей попытки. При неопределённом ответе заказ остаётся заблокированным до сверки; обращаться к оператору нужно с OrderId из `payment_orders`, без пароля терминала. После неопределённого исхода нельзя вручную удалять заказ или сбрасывать `active_document` без проверки банка.

Удаление договора блокируется, пока есть незавершённый платёж. Финансовые записи сохраняются отдельно от текста договора. Для создания новых платежей установлен лимит 10 попыток за 10 минут на аккаунт; запросы статуса одного заказа обращаются в банк не чаще одного раза в 5 секунд.

После двух минут `CheckOrder` может разрешить повторную попытку, если банк явно вернул код `335` — заказ не существует на данном терминале. Освобождается только исходная запись `INITIALIZING`, без PaymentId и ссылки, с нулевым рангом статуса. Общая ошибка банка или неопределённый ответ не снимает блокировку. Это проверено на реальном DEMO-терминале и в интеграционных тестах. [Справочник ошибок Т-Банка](https://developer.tbank.ru/eacq/intro/errors/error-codes).

Для закрытого теста в Sites используется отдельная DEMO-служба на существующем VPS Hostinger. Описание установки и ограничений: [services/tbank-gateway/README.md](../services/tbank-gateway/README.md). Пароль терминала остаётся в Sites. Подтверждение оплаты в закрытой копии сверяется запросом к банку; публичный приём уведомлений для боевого запуска ещё не включён.

## Настройки сервера

Пример без секретов: `.env.example`. Для локального Worker его можно скопировать в игнорируемый `.dev.vars`. На хостинге значения задаются как серверные переменные / секреты. Они не попадают в JavaScript браузера или `.openai/hosting.json`.

| Переменная | Значение |
| --- | --- |
| `TBANK_ENABLED` | `true` только после завершения настройки; по умолчанию приём платежей отключён |
| `TBANK_TERMINAL_KEY` | Терминал выбранного магазина; сначала тестовый DEMO |
| `TBANK_PASSWORD` | Секретный пароль того же терминала |
| `TBANK_PUBLIC_URL` | `https://criterion-publish-diagnostic-20261113.serenewisteria2.chatgpt.site` — адрес новой закрытой копии, HTTPS origin без пути и параметров |
| `TBANK_API_URL` | По умолчанию `https://securepay.tinkoff.ru/v2/`; тестовый API `https://rest-api-test.tinkoff.ru/v2/` — только если указан банком |
| `TBANK_RECEIPT_MODE` | Выбран `bank`: «Чеки Т-Бизнеса», данные Receipt передаются в Init |
| `TBANK_TAXATION` | `usn_income` — подтверждена АУСН «Доходы», ставка 8%; Т-Банк принимает для неё этот код |
| `TBANK_TAX` | `none` — без НДС для собственных услуг Criterion при подтверждённой продавцом АУСН |
| `TBANK_PAYMENT_METHOD` | `full_payment` — полный расчёт, готовый договор открывается сразу после оплаты |
| `TBANK_PAYMENT_OBJECT` | `service` — услуга создания договора |

Без настроенного режима чеков checkout не включается. `external` не создаёт и не отправляет чек сам: требуется отдельная система. Налоговые реквизиты следует подтвердить у продавца / бухгалтера. Если используется предоплата, отдельно обеспечить чек зачёта предоплаты по принятой схеме; в этой версии реализован чек, передаваемый в Init, а не универсальный фискальный учёт.

## Выбранный сервис чеков

13 ноября 2026 пользователь выбрал и подключил «Чеки Т-Бизнеса» с комиссией 1,5% с платежа. При цене договора 199 ₽ это около 2,99 ₽ за чек; комиссия эквайринга учитывается отдельно. В `.env.example` установлен `TBANK_RECEIPT_MODE=bank`. Приём платежей в приложении остаётся выключенным до заполнения остальных параметров, публикации и тестирования.

Пользователь самостоятельно принял [оферту](https://static.cloudpayments.ru/docs/TChecks.pdf). По редакции от 16 октября 2026 услугу оказывает ООО «КЛАУДКАССИР», комиссия 1,5% включает НДС. Банк передаёт исполнителю сведения о продавце, email покупателя и данные расчёта для формирования и отправки чеков. В кабинете магазина Criterion проверен итоговый статус «Чеки Т-Бизнеса — Подключено».

## Налоговые реквизиты: АУСН

Пользователь подтвердил АУСН «Доходы» со ставкой 8%. Для реализации собственных услуг Criterion предусмотрено «Без НДС» (`TBANK_TAX=none`); это не ставка 0%. [ФНС](https://www.nalog.gov.ru/rn77/taxation/taxes/nds_usn/) указывает, что плательщики АУСН не признаются плательщиками НДС, за исключением ввоза товаров и исполнения обязанностей налогового агента.

В [описании Init Т-Банка](https://developer.tbank.ru/eacq/api/init) АУСН передаётся через значения `Taxation`, соответствующие объекту налогообложения:

| Объект АУСН | `TBANK_TAXATION` |
| --- | --- |
| Доходы | `usn_income` |
| Доходы минус расходы | `usn_income_outcome` |

В `.env.example` сохранён подтверждённый вариант `TBANK_TAXATION=usn_income`. Не отправлять вымышленное значение `ausn`. Эта настройка изменяет реквизит чека, а не налоговый режим продавца. Ставка АУСН 8% не передаётся как НДС и не прибавляется к цене договора: покупатель платит 199 ₽.

Особенность выбранного сервиса: [Т-Банк требует при АУСН вручную вносить итоговые суммы доходов в личный кабинет ФНС](https://www.tbank.ru/business/help/business-payments/internet-acquiring/kassa/check/). Отправка чеков сервисом не заменяет этот шаг налогового учёта. В приложении автоматической передачи таких итогов в кабинет АУСН нет.

## Запуск

1. Перенести подтверждённые налоговые настройки (`TBANK_TAXATION=usn_income`, `TBANK_TAX=none`) на сервер; согласовать способ расчёта и предмет расчёта. «Чеки Т-Бизнеса» уже подключены в кабинете магазина Criterion.
2. Развернуть код с добавочной миграцией `0003_brown_joseph.sql`. Прежние миграции не менять и не запускать повторно вручную. Миграция добавляет две таблицы и два поля документов, не удаляя данные.
3. Настроить серверные секреты тестового терминала и HTTPS origin. В кабинете этого терминала включить HTTP-уведомления на `https://criterion.andreyvitko.com/api/payments/tbank/notification`. Этот адрес должен быть доступен банку без входа в аккаунт, но проверять подпись каждого события.
4. `SuccessURL` и `FailURL` передаются при Init вместе с ID договора. Страницы банка по умолчанию могут оставаться резервными настройками терминала.
5. В тестовом окружении пройти сценарии банка: успех, отказ, закрытие формы, повтор уведомления, задержка ответа и возврат. Проверить настоящую доставку HTTP-уведомления и формирование тестового чека.
6. После тестов заменить тестовые секреты на рабочие, подтвердить настройки рабочего терминала и выполнить контролируемую первую оплату. Не переключать терминал при наличии незавершённых тестовых заказов в используемой базе; использовать отдельную тестовую базу.

Тестовый и рабочий режимы не определяются браузером: они задаются исключительно серверной конфигурацией. Автоматическая сверка статуса выполняется после возврата из банка и по кнопке «Проверить оплату»; дополнительно банк повторяет недоставленные уведомления. Фонового расписания сверки в этой версии нет.

Для исходного сайта `criterion.andreyvitko.com` запросы доступа к исходникам и секретам вернули `Sites project not found`. Пользователь выбрал новую закрытую копию без старых аккаунтов и договоров. Этот checkout относится к отдельному проекту Sites с адресом `https://criterion-publish-diagnostic-20261113.serenewisteria2.chatgpt.site`, доступным только владельцу. Исходный проект и его база не изменены. OpenAI подключён отдельным ключом Codex-Criterion; первый неиспользуемый ключ отозван. Рабочие секреты банка и почты из исходного проекта не переносились.

Настройки банка по адресу `criterion.andreyvitko.com` выше относятся к исходному магазину. Не переключать их на новую копию до подготовки отдельного тестового контура. В закрытую копию банк не сможет доставлять обычные HTTP-уведомления без поддерживаемого внешнего доступа; доступ владельца в браузере не является доступом банка. В этой закрытой копии `TBANK_ENABLED=true` только для DEMO-терминала; реальных списаний нет. Перед запуском эквайринга отдельно согласовать адрес магазина и доступность подписанных уведомлений, не меняя закрытый доступ автоматически.
