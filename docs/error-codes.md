# Действия при ошибке API

Используйте поле `code` ответа и журнал по `requestId`. Поле `error` содержит сообщение для пользователя. Техническую причину может уточнить `causeCode` из допустимого перечня, а статус провайдера — `upstreamStatus`. Приведённые ниже тексты описывают смысл сообщения. Конкретная формулировка уточняет действие на соответствующем маршруте.

| Код или семейство | Что произошло | Действия |
| --- | --- | --- |
| `BAD_REQUEST`, `METHOD_NOT_ALLOWED`, `VALIDATION_ERROR`, `PAYLOAD_TOO_LARGE`, `UNSUPPORTED_MEDIA_TYPE` | Не удалось принять или разобрать данные запроса | Исправить запрос, его размер или формат. Повтор исходного запроса не помогает. |
| `UNAUTHORIZED`, `FORBIDDEN`, `PAYMENT_REQUIRED`, `NOT_FOUND` | Для действия требуется вход, разрешение, оплата либо доступный объект | Проверить сессию и состояние документа. |
| `CONFLICT`, `RATE_LIMITED` | Изменилась версия документа, уже выполняется операция или исчерпан лимит | Обновить состояние или дождаться окончания ограничения. |
| `UNAVAILABLE`, `REQUEST_TIMEOUT`, `INTERNAL_ERROR` | Операция недоступна, не успела завершиться или вернула неизвестное исключение | Найти этап в журнале и проверить, сохранился ли результат. |
| `DATABASE_ERROR`, `CLEANUP_FAILED` | Сбой доступа к SQLite или завершения операции | Проверить `storage.snapshot`, доступ к тому, свободное место и состояние блокировок. |
| `MAIL_SEND_FAILED` | Провайдер почты не подтвердил выполнение | Найти событие операции и статус провайдера. Публичный ответ сброса пароля сохраняет конфиденциальность аккаунта. |
| `PRIVACY_ERROR` | Защита данных остановила обработку | Проверить доступность Python-сервиса. Диагностировать на вымышленных данных. |
| `AI_TIMEOUT`, `AI_NOT_CONFIGURED`, `AI_UNAVAILABLE`, `AI_RATE_LIMITED`, `AI_INVALID_RESPONSE` | Модель не ответила вовремя, не подключена, отклонила запрос или вернула неподходящий результат | Сверить этап операции, статус и настройки. Проверить сохранённую версию перед повтором. |
| `PAYMENT_ERROR`, `PAYMENT_UNAVAILABLE` | Конфигурация оплаты либо состояние заказа препятствуют действию | Уточнить состояние заказа и настройки терминала. |
| `GATEWAY_*` / `BANK_*` с окончаниями `DNS_ERROR`, `CONNECTION_REFUSED`, `CONNECT_TIMEOUT`, `TLS_ERROR`, `TIMEOUT` | Ошибка разрешения адреса, отказ соединения, таймаут подключения, TLS или исчерпание полного бюджета | Сверить компонент и сетевые времена. Для TLS проверить сертификаты и часы. Для таймаута выяснить, на каком участке истёк срок. |
| Те же префиксы с `HTTP_ERROR`, `RESPONSE_INVALID`, `RESPONSE_INTERRUPTED`, `NETWORK_ERROR` | Ошибочный статус, нечитаемый ответ, обрыв при чтении либо причина сетевого сбоя не установлена | Проверить `upstreamStatus` и результат последующей сверки заказа. |
| `BANK_REQUEST_REJECTED` | Банк ответил явным отказом на уровне своего API | Проверить сохранённый статус и метод запроса. |

Для платёжных записей `retryable` относится к конкретному методу. После сбоя создания оплаты следует проверить уже существующий заказ. Пропуск поля означает, что решение о повторе не задано. Подробнее о механизме восстановления — в [руководстве по оплате](payment-flow.md).
